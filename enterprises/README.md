# 企业专属目录与更新方式

通用程序留在仓库根目录；每个企业的专属代码、模板和运行状态集中到 `enterprises/<企业标识>/`。一次服务进程只使用一个企业目录。

## 目录约定

```text
enterprise-carbon-account/
├─ app.py、config.py、enterprise_paths.py
├─ core/、adapters/、hooks/、static/、database/  # 通用程序
├─ normalizers/                            # 通用基类和编写示例
├─ presets_packs/                          # 通用预设包示例
├─ tools/                                  # 通用维护工具与回归测试
├─ .enterprise.local.json                  # 本机选用哪个企业，Git 忽略
└─ enterprises/
   ├─ README.md                           # 本说明，可进入 Git
   └─ <企业标识>/                         # 整个企业目录均被 Git 忽略
      ├─ data/                            # 数据库、报告、图片、归档、备份、日志
      ├─ normalizers/                     # 企业接口认证、请求和报文转换
      ├─ templates/reports/docx/          # 企业 Word 模板、显示名和自定义占位符
      ├─ presets_packs/                   # 可选企业 Python 预设包
      ├─ tools/                           # 企业专用维护、诊断及验收工具
      ├─ docs/                            # 企业手册、验收记录和私有清单
      ├─ enterprise.json                  # 企业目录描述
      └─ README.md                        # 企业安装与迁移说明
```

`data/` 是企业运行状态，包含真实凭据和历史业务数据，不是每次升级都覆盖的安装资源。

## 选择企业目录

方式一：在仓库根目录新建 `.enterprise.local.json`：

```json
{"directory": "enterprises/your_company"}
```

方式二：PowerShell 在启动进程前设置环境变量：

```powershell
$env:CARBON_ENTERPRISE_DIR = 'enterprises/your_company'
python serve.py
```

环境变量优先于本机选择文件；相对路径相对于仓库根目录，也支持绝对路径。修改、放入或移出企业包后须重启服务。

**不设置上述两种方式也可以自动识别：** `enterprises/` 中恰好一个带合法 `enterprise.json` 的企业包时，自动使用该包；没有包时使用 `enterprises/default/` 的独立通用数据；多个包时要求明确选择，不合并或猜测。描述文件最小格式为 `{"id":"your_company","display_name":"示例企业","layout_version":1}`，id 必须与文件夹名一致。

本机选择文件所指企业包被移除后，会提醒并进入通用模式，不转用其他企业。环境变量显式指定的普通企业目录缺失时仍拒绝启动，避免正式部署因路径或挂载错误误用空库。想保留企业包同时进入通用模式，可设置 `$env:CARBON_ENTERPRISE_DIR = 'enterprises/default'`。

建议停止服务后把整个企业包移到仓库外保存，而不是删除包含生产数据的包。恢复通用只改变加载来源，不清空或改写企业数据；把包放回并选中、重启后仍使用原数据。

不要让两个运行中的服务写入同一 SQLite 数据库。不同企业分别使用不同目录、进程和端口；本功能没有把现有系统改造成多租户平台。

## 首次交付

1. 获取与企业适配包配套的通用代码和依赖。
2. 把带有 `enterprise.json` 的获授权企业文件夹放到 `enterprises/` 中；仅有一个包时自动识别，多包时设置本机选择文件或环境变量。
3. 全新企业使用空的数据目录并通过系统初始化配置；禁止拿其他企业的生产数据库改名字当新企业。
4. 原企业迁机时，停止所有写入后成套迁移企业目录。数据库与图片、历史报告、归档附件必须一起保留。
5. 配置 Python 环境，启动前核对选中的数据库、转换器和报告模板。服务入口仍为 `python serve.py`。

## 后续更新

- 通用代码通过 Git 发布明确版本；升级前备份企业目录和当前代码版本，并阅读该版数据库迁移说明。
- 同企业升级保留当前 `data/`，只按发布清单更新指定适配代码或模板。其他企业的新适配包不应覆盖现有企业目录。
- 修改企业模板、预设包也需要版本和变更记录；企业技术人员自己的改动要先比对，不能直接覆盖。
- 回退程序前确认数据库版本兼容；若升级改过数据库，仅回退代码不一定足够。
- 当前提供了目录隔离和加载机制，还没有自动升级器、自动模板合并器或跨版本兼容保证。

## 兼容范围

原机器配置中的 `{"hook":"企业转换器文件名"}` 无需改动。系统把当前企业 `normalizers/` 接入加载路径，通用基类仍留在根目录。企业模板根目录仍支持企业名称子目录，因此原有模板引用如 `企业名/pdd.docx` 可以保留。

历史 `data/...` 引用，以及旧 `.../enterprise-carbon-account/data/...` 的绝对路径，在读取报告和预设图片时映射到当前企业的数据目录。新报告数据库引用保存为 `data/reports/...`，便于迁机。映射只能找到仍存在的原文件，不能恢复已经缺失的文件。

`.gitignore` 只阻止常规的新文件跟踪，不加密文件，也不会自动取消已跟踪的私有文件。首次发布前还须核对 Git 已跟踪清单。

本次检查发现旧位置的鑫钻转换器、区划辅助文件与 Word 模板曾被 Git 跟踪。当前工作区已将它们迁到被忽略的私有目录；后续发布本次通用版本时，应提交旧位置文件的删除及新的通用加载代码。本次没有提交或推送，也没有改写 Git 历史，历史提交中的旧企业文件不会因搬迁而消失。

后续 AI 适配前必须先阅读仓库根目录 [AGENTS.md](../AGENTS.md)，其中规定加载约定、扩展边界、数据隔离和验收要求。
